# ah-app — the single-user experience (client plane)

The React/TypeScript SPA for the Alternate Histories single-user product
(DN-3 architecture, decisions W1–W10; kickoff `Instructions/KICKOFF-PRODUCT-SU.md`).

## What this is

The browser side of a strict two-plane split:

- **This app renders and asks.** It consumes a *world bundle* (`ah bundle
  RUN_ID` on the Python side; <1 MB gzip, the W2 contract) and renders the
  decade: fan charts, the revealed path, the reveal pointer, and (from
  su-app-02 on) the decision windows.
- **The session service decides.** Anything that scores — the reveal
  pointer during play, decisions, outcomes — is server state
  (`uv run uvicorn ah.serve:app --port 8787`). The app never computes a
  result it could be trusted to fake.

The bundle's numeric tape carries a t0 seal (SHA-256 over the row-major
float64 bytes); the app **re-seals what it received and displays the
verdict**, so a rewritten history is caught in the client, not just claimed
by the server.

## Commands

```bash
npm install
npm run dev        # Vite dev server; /sessions proxies to :8787
npm run test       # vitest (bundle loader + seal against the committed fixture)
npm run typecheck  # tsc --noEmit
npm run build      # production build
```

## Layout

- `src/lib/bundle.ts` — bundle fetch/parse/shape-check + client-side seal
- `src/lib/idb.ts` — IndexedDB cache (W8: a loaded world replays offline)
- `src/components/FanChart.tsx` — SVG percentile cone + revealed path clip
- `src/App.tsx` — the v0.1 shell (browse mode; session binding is su-app-02)
- `fixtures/toy.bundle.gz` — a committed bundle generated by the Python side,
  shared by both test suites so the two seal implementations stay pinned

No chart library, no state framework — every dependency is one someone must
justify deleting later (the repo's working convention, applied to npm).
