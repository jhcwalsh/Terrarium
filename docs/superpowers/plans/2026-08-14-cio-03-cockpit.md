# CIO-03: Cockpit Cutover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The CIO dashboard becomes *the* play surface — a cockpit whose panes fit one screen, with the wire and the decision window beside it, the retired book panels gone, and the inherited debts from cio-02 closed.

**Architecture:** `CioDashboard` gains an *embedded chrome* mode (host owns the plane control and the footer; host may inject extra tabs) and a class hook so `styles.css` can size it. `Play.tsx`'s `.vgrid` becomes a two-column cockpit in CIO mode: the dashboard pane scrolls internally (only it — never the whole vitrine), and the right column carries the wire and the decision panel. The peer-cone fan charts survive as a host-supplied "Peers" tab, which keeps `CioDashboard` a pure renderer of one `CioView` (DN-8 §1) rather than a component with two data sources.

**Tech Stack:** React 18 + TypeScript 5.7 + Vite 6, vitest + happy-dom. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-14-cio-dashboard-design.md` §6 (bullets 3–5: the cockpit). Contract: `Instructions/DN-8-cio-dashboard-data-contract.md`.

## Global Constraints

- Branch `cio-03-cockpit`, merged `--no-ff` into `main` only after the full gate is green and `scripts/check_gate.py` stamps `.gate-ok`. Controller runs the gate, the browser verification, and the merge.
- **The one-screen contract** (`app/src/styles.css:129-134`, quoting the owner: the player must see everything on one screen without scrolling) is the invariant this WP exists to restore. In CIO mode the header, ticker, stat rail, right column, and footer must NOT move when the dashboard's content is tall; only the dashboard pane itself may scroll, and only within its own box.
- `CioDashboard` stays a **pure renderer of one `CioView`** — it computes nothing beyond DN-8 §8's permitted list, and it never gains a second numeric data source. Host-injected tabs render host-owned content; the dashboard just hosts the slot.
- The server remains the authority for value and scoring. No client-side value or alpha computation is added.
- No new npm dependencies. All charts stay hand-rolled SVG.
- Do not touch `AnalysisChart.tsx` — despite appearing in this WP's retirement discussion, it is a **Reckoning** dependency (`app/src/Reckoning.tsx:19,80`), not a Play one, and `Reckoning.test.tsx` pins it.
- Gates: `cd app && npm run typecheck && npm run test && npm run build` green with pristine output (the pre-existing `act(...)` warnings are known and not this WP's to fix); Python side: full pytest suite, ruff, pyright clean.
- Every removal is a **retirement**, not a test weakening: when a component's job moves to the dashboard, its component file and its render-level test go together, and any pure helper still under test either moves with its test or stays with a stated reason.
